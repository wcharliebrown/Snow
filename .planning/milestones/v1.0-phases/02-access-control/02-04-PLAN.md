<task type="auto">
  <name>Task 1: Add group membership save logic to the edit POST handler</name>
  <files>functions/admin-users.php</files>
  <action>
In the edit POST handler branch (`elseif ($postAction === 'edit' && $userId)`), inside the `if (!$error)` block, after the `dbUpdate('users', $fields, 'id = ?', [$userId]);` call and BEFORE the `header('Location: /admin/users?msg=updated'); exit;` lines, add:

```php
// Save group memberships: delete all existing, insert new selections
$newGroupIds = array_filter(array_map('intval', (array)($_POST['groups'] ?? [])));
dbQuery("DELETE FROM user_groups WHERE user_id = ?", [$userId]);
foreach ($newGroupIds as $gid) {
    dbInsert('user_groups', [
        'user_id'      => $userId,
        'group_id'     => $gid,
        'created_date' => date('Y-m-d H:i:s'),
    ]);
}
```

This approach (DELETE + INSERT) is intentional: it handles additions, removals, and no-change in a single code path. The UNIQUE KEY on (user_id, group_id) prevents duplicates if a bug causes double insert, but the DELETE ensures clean state.

The `$_POST['groups']` key is used (not `groups[]` in PHP — PHP normalizes `name="groups[]"` POST values to `$_POST['groups']` as an array).

No validation needed on group IDs beyond intval() — invalid IDs will fail the FK constraint and the dbInsert will throw, which is acceptable behaviour. The admin UI only shows valid active groups.
