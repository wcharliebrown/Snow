<!-- Key correctness invariants to verify — from 04-RESEARCH.md Pitfall 5 -->

Textarea display correctness:
- The edit form for admin-pages.php must use htmlspecialchars() on the content value in the textarea attribute:
  <textarea name="content"><?= htmlspecialchars($editPage['content'] ?? '') ?></textarea>
  This is CORRECT — htmlspecialchars in a textarea prevents form rendering issues without affecting DB storage.
- The pages.php renderPage() or template rendering of $page['content'] must NOT apply htmlspecialchars:
  It must output content raw so HTML tags in the stored content render as HTML, not as escaped text.
  Check: grep for 'htmlspecialchars.*content\|content.*htmlspecialchars' in functions/pages.php and functions/template.php

sendEmailTemplate() signature (from email.php — already implemented):
  sendEmailTemplate(string $templateName, string $to, array $data): bool
  Internally calls processTokens($template['body'], $data) — replaces {{key}} with htmlspecialchars($data['key']).

processTokens() from template.php:
  processTokens(string $template, array $data): string
  Replaces {{variable}} tokens. Already tested in existing test suite.
