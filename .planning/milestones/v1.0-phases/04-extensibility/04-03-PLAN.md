Hook execution pattern (from 04-RESEARCH.md — use exactly):
```php
// GET branch — before form render, after $tableDef is loaded:
$preHook = $tableDef['pre_edit_php_filename'] ?? null;
if ($preHook) {
    $hookPath = SNOW_FUNCTIONS . '/' . $preHook;
    if (file_exists($hookPath)) {
        try {
            include $hookPath;
        } catch (Throwable $e) {
            logError("pre_edit hook '{$preHook}' failed for table '{$tableName}': " . $e->getMessage());
        }
    }
}

// POST branch — after successful dbUpdate() or dbInsert(), before redirect:
$postHook = $tableDef['post_edit_php_filename'] ?? null;
if ($postHook) {
    $hookPath = SNOW_FUNCTIONS . '/' . $postHook;
    if (file_exists($hookPath)) {
        try {
            include $hookPath;
        } catch (Throwable $e) {
            logError("post_edit hook '{$postHook}' failed for table '{$tableName}': " . $e->getMessage());
        }
    }
}
// Then existing redirect immediately follows
```

Read functions/admin-custom-table.php in full to locate the two insertion points:

INSERTION POINT 1 — GET branch (edit form render):
Find where $tableDef is loaded (a dbGetRow call for the custom_tables row by $tableId or $tableName). After $tableDef is confirmed to exist and before the edit form HTML begins (the ob_start() or the ?>  that starts the form HTML), insert the pre_edit hook block:

```php
// EXT-01: Execute pre_edit hook if registered for this table
$preHook = $tableDef['pre_edit_php_filename'] ?? null;
if ($preHook) {
    $hookPath = SNOW_FUNCTIONS . '/' . $preHook;
    if (file_exists($hookPath)) {
        try {
            // $record is in scope: existing row data for edit, [] for add
            include $hookPath;
        } catch (Throwable $e) {
            logError("pre_edit hook '{$preHook}' failed for table '{$tableName}': " . $e->getMessage());
        }
    }
}
```

INSERTION POINT 2 — POST branch (after successful save):
Find the edit POST handler where dbUpdate() is called on the custom table row. Find the add POST handler where dbInsert() is called. In BOTH locations, after the successful DB write and before the header('Location: ...') redirect, insert the post_edit hook block:

```php
// EXT-01: Execute post_edit hook if registered for this table
$postHook = $tableDef['post_edit_php_filename'] ?? null;
if ($postHook) {
    $hookPath = SNOW_FUNCTIONS . '/' . $postHook;
    if (file_exists($hookPath)) {
        try {
            // $record/$insertedId available in scope for hook context
            include $hookPath;
        } catch (Throwable $e) {
            logError("post_edit hook '{$postHook}' failed for table '{$tableName}': " . $e->getMessage());
        }
    }
}
```

Critical: The post_edit hook MUST execute before the redirect header() call. The redirect must still happen regardless of hook success or failure.

Critical: Use catch (Throwable $e) — not catch (Exception $e). PHP fatal errors and syntax errors in hook files are Throwable but not Exception.

Do not add hooks to the delete action.
