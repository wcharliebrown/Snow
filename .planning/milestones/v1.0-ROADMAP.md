# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-03-17
**Phases:** 1–5
**Total Plans:** 28

## Overview

Snow's v1.0 MVP builds a complete admin framework on top of the existing LAMP stack. Starting from CSRF/session security, the milestone layers in row-level ACL, full version history with rollback, table snapshots, PHP hook extensibility, 2FA login, custom pages/email templates, and finally search/sort/filter UX with scheduled row lifecycle. Every phase depended on the previous — the order was driven by the dependency graph.

## Milestone Summary

**Key Decisions:**

- Sessions: SELECT FOR UPDATE inside transaction in read(); write() commits — concurrent request serialization
- Sessions: sessions.user_id updated via separate UPDATE in loginUser() — write() runs before user identity known
- CSRF: Per-session tokens (not per-request) — avoids back-button and multi-tab breakage
- CSRF: Central enforcement in renderPage() before custom_script include — one insertion protects every page
- ACL: view_groups/edit_groups stored as VARCHAR(500) comma-separated group IDs; NULL means open to all table_management users
- ACL: table_data_access is a separate permission from table_management — data users reach admin/data/* but cannot touch schema
- ACL: Sentinel null used to distinguish do-not-write from empty-array (open-to-all) in POST handlers
- Snapshots: snapshot_table name = snapshot_{table}_{YYYYMMDDHHmmss}{rand(100,999)} — sortable + collision-safe
- Snapshots: Restore uses RENAME TABLE (DDL, auto-commits) — no transaction wrapper; rely on MySQL two-pair atomicity
- Snapshots: Pre-restore auto-snapshot gives admin a named recovery point before any destructive rename
- Hooks: Hook errors silently logged via logError() — redirect proceeds regardless; empty filename stored as NULL
- 2FA: Fork in login.php (not auth.php) keeps loginUser() reusable; explicit unset(user_id) is critical security invariant
- Search: Simple and advanced search mutually exclusive via $advActive flag — when adv[] non-empty, q param ignored
- Search: Sort field validated against allowlist of visible field names + standard columns — no SQL injection path
- Schedule: activate_at/deactivate_at/delete_at columns added per-table via provisioning, not to central schema

**Issues Resolved:**

- Phase 1: ALTER TABLE ADD COLUMN IF NOT EXISTS is MariaDB-only — MySQL 8.0 requires PREPARE/EXECUTE via INFORMATION_SCHEMA
- Phase 1: LONGTEXT/BLOB columns cannot have DEFAULT values in MySQL 8.0 strict mode
- Phase 2: view_groups_raw/edit_groups_raw phantom key bug in add/edit form array handling
- Phase 3: renderPage() called with path string not array — framework expects file path string
- Phase 4: login_otp FK violation with hardcoded user_id=0 — fixed to resolve real user via SELECT FROM users LIMIT 1
- Phase 4: login_otp email template body fixed — {{first_name}} and {{otp_code}} tokens were missing
- Phase 5: assertTrue(!empty($col)) used instead of assertNotNull for INFORMATION_SCHEMA checks (dbGetRow returns false not null)

**Issues Deferred:**

- TOTP/Google Authenticator (AUTH-V2-01) — deferred to v2; SEC-05 uses email OTP only
- Field-level encryption (ADV-V2-01) — deferred to v2
- Bulk import/export (ADV-V2-02) — deferred to v2

**Technical Debt Incurred:**

- Phase 1 migration blocks use ALTER TABLE per-column individually; could be batched if schema grows large
- Flat-file activity log write is unconditional alongside DB — dual-write overhead on every log event
- processScheduledActions() defined in admin-custom-table.php; test file uses function_exists() guard for CLI context
